# 【最重要・絶対厳守ルール】※冒頭に提示
1. **要約禁止**：発言を勝手に短くしない。元音声の8〜9割の情報量を保つ。
2. **3列表形式**：議事内容は必ずMarkdownパイプ表（|符号|議題・議事内容|決定・確認事項|）の3列で記述する。
3. **発言者は末尾に括弧書き**：`（〇〇 〇〇）` の形式。敬称略。例：`（ニッケン 君島）`、`（日比野設計 門間）`
4. **章番号と項番号**：1[工事進捗報告] → 1-1, 1-2, 1-3 のように階層化。
5. **会社名は必ず「ニッケン建設」**：「日建建設」「日建」などになっていても**必ずニッケン建設**と修正。
6. **指定フォーマット厳守**：以下の出力フォーマットを一字一句守る。

# 詳細指示

## 1. 音声認識エラーの修正
建築用語・固有名詞の誤変換を文脈から推測して修正：
- 杭打ち工事、根切り、捨てコン、墨出し、補強アンカー、土工事、土砂搬出、配筋、大梁、スラブ、基礎立ち上がり、土留め、L型擁壁、ジョリパット、エラクリート、スタイロフォーム、耐火被覆、錆止め塗料 など
- 案件名・工事名は固有名詞として正しい表記で統一

## 2. ノイズ除去
**【相槌・フィラーは徹底的に削除】**
- 削除対象：「はい」「ええ」「うん」「うんうん」「なるほど」「なるほどなるほど」「そうそう」「ふんふん」「そうですね」「ですね」「あー」「えー」「あのー」「えーっと」「うーん」「まあ」「まー」「ま」「えっと」「そのー」「ちょっと」（独立した語として）
- 連続相槌（例：「あー、はい、はい、なるほど」）は1文字も残さず削除
- **削除しないもの**：「分かりました」「了解しました」「承知しました」「いえ」「違います」（意思表示・否定の意味のある発言）

## 3. 出席者の役割別整理
出席者は **役割別** に記載する：
- 発注者（施主・〇〇会等）
- 設計監理（〇〇設計）
- 総合施工（ニッケン建設）
- 設備・関連業者（各社）

役割が判明しない場合は推測して分類。欠席の場合は「欠席」と明記。

## 4. 議題の構造化（最重要）
議論内容を以下の章で分類：
- 1[工事進捗報告]
- 2[工事監理者の報告]
- 3[施工者より工程の説明]
- 4[発注者からの指示及び伝達事項]
- 5[監理者からの指示及び伝達事項]
- 6[施工者からの実情、連絡事項]
- 7[その他、伝達事項]

各章の中で個別の議題は `1-1`, `1-2`, `1-3` のように番号付け。
**章タイトル行は3列とも同じ内容**（`1[工事進捗報告]` を3セルに記載）。

## 5. トーン＆マナー
- 敬体（です・ます調）で記述
- 発言の末尾に発言者を `（会社名 氏名）` の形で記載（敬称略）
- 決定・確認事項は短く明確に
